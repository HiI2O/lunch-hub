## DTO バリデーション

### LoginRequestDto

設計根拠: [API設計 > ログイン](../../03-api-design.md)

リクエストボディ: `{ email: string, password: string }`

#### email

- [ ] 正常: `"user@company.com"` → バリデーション通過
- [ ] 異常: `"not-an-email"` → バリデーションエラー（メール形式）
- [ ] 異常: `""` 空文字 → バリデーションエラー
- [ ] 異常: `null` / 未指定 → バリデーションエラー（必須）

#### password

- [ ] 正常: `"Password1!"` → バリデーション通過
- [ ] 異常: `""` 空文字 → バリデーションエラー（空でない文字列）
- [ ] 異常: `null` / 未指定 → バリデーションエラー（必須）

### ActivateRequestDto

設計根拠: [API設計 > アカウントアクティベーション](../../03-api-design.md)

リクエストボディ: `{ token: string, password: string, displayName: string }`

#### token

- [ ] 正常: 任意の文字列 → バリデーション通過
- [ ] 正常: `""` 空文字 → バリデーション通過（`@IsString` のみ、`@IsNotEmpty` なし）
- [ ] 異常: `null` / 未指定 → バリデーションエラー（必須）

#### password

- [ ] 正常: `"Password1!"` （英字・数字・特殊文字を含む8文字以上）→ バリデーション通過
- [ ] 異常: `"short1!"` （8文字未満）→ バリデーションエラー（最小8文字）
- [ ] 異常: `"password1"` （特殊文字なし）→ バリデーションエラー（パターン不一致）
- [ ] 異常: `"Password!"` （数字なし）→ バリデーションエラー（パターン不一致）
- [ ] 異常: `"12345678!"` （英字なし）→ バリデーションエラー（パターン不一致）
- [ ] 異常: `""` 空文字 → バリデーションエラー
- [ ] 異常: `null` / 未指定 → バリデーションエラー（必須）

#### displayName

- [ ] 正常: `"田中太郎"` （1〜50文字）→ バリデーション通過
- [ ] 境界値: 1文字（例: `"A"`）→ バリデーション通過（最小値）
- [ ] 境界値: 50文字 → バリデーション通過（最大値）
- [ ] 異常: `""` 空文字（0文字）→ バリデーションエラー（最小1文字）
- [ ] 異常: 51文字以上 → バリデーションエラー（最大50文字）
- [ ] 異常: `null` / 未指定 → バリデーションエラー（必須）

## テスト対象外（理由付き）

| 対象 | 理由 |
|------|------|
| class-validator デコレータの動作そのもの | フレームワークが保証。DTO テストはビジネスルールの反映を確認 |
| Controller のリクエスト処理 | Controller テスト（`auth.controller.spec.ts` 等）で検証済み |
| ドメインのパスワードポリシー詳細 | Domain 層の VO テストで検証。DTO はリクエスト段階の入力チェックのみ |
